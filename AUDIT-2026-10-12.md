# Проверка AutoTurn — 12 октября 2026

Локальная версия: **0.2.0-dev, сборка 18**. Intel Mac, macOS 15.8.1,
Swift 6.1.2. Исходники предыдущей сборки 17 импортированы в пустую папку
этого проекта; прежний рабочий каталог сохранён. Ветка: `codex/full-app-audit`.

## Исправления

| Проблема | Результат |
|---|---|
| CIDR с лишними `/`, пустыми компонентами или знаком `+` проходил проверку | Некорректные записи отклоняются до применения маршрутов |
| Нулевой символ внутри IP скрывал остаток строки от `inet_pton` | Проверка отклоняет всю строку, включая IP-списки и CIDR |
| Некорректные hostname и IPv6 без скобок принимались как Endpoint | Проверяются метки hostname, IPv4 и формат `[IPv6]:port` |
| IPC пропускал превышение лимита при переводе строки в той же порции данных | Размер проверяется до возврата команды; ровно на лимите строка разрешена |
| Остановка возвращала `ok=true` при ошибке очистки PF | Команды возвращают ошибку; чтение статуса остаётся доступным |
| Переключение профиля оставляло старое ядро маршрутов работающим | Сначала усиливается PF, затем останавливаются ядро маршрутов и старый туннель |
| После аварии AWG старый интерфейс/маршрут мешал новому запуску | Остатки очищаются до повторного запуска; ожидание проверки связи сбрасывается |
| Служба без профилей показывала «домашняя сеть» | Показывается состояние настройки и предложение импортировать профиль |
| Проверка обновления допускала подписанный пакет без ядра маршрутизации | Проверяются все четыре universal-компонента; установщик проверяет комплектность до остановки текущей службы |
| Отрицательные компоненты macOS принимались в подписанных метаданных | Допускаются только непустые десятичные компоненты |

Дополнительно IPC повторяет чтение/запись после `EINTR`. Регрессии включены
в `scripts/test.sh`; проверки пакета и конфигураций ядра добавлены в CI.

## Живой тест установленного приложения

Используется сохранённый профиль; ключи не выгружаются в файл и не печатаются.
Обычный процесс временно закрывается, чтобы сетевые наблюдения не вмешивались
в диагностическую конфигурацию.

Проверены настоящий TUN/PF/AWG, прямой HTTPS и выбранный HTTPS через VPN,
домашний режим с удалением TUN/PF, полный VPN, выключение и очистка.
Домашний SSID **синтетический**: это проверка политики, не физическое переключение Wi-Fi.

Хеши сериализованных сохранённых настроек до/после совпадают. После проверки
маршрут к `1.1.1.1` идёт через физический `en0`; `utun99` и собственные
DNS-ключи AutoTurn отсутствуют; обычный HTTPS возвращает 200.
Приложение запускается снова с сохранёнными настройками.

## Границы проверки

Отсутствие любых возможных ошибок не гарантируется. Не выполнены физический
VPN-тест на M1, реальное переключение Wi-Fi в режиме правил, сон/пробуждение,
выход/вход пользователя, captive portal, реальный IPv6-трафик и все варианты
браузерного DoH/ECH. ARM-компоненты собраны, но на этом Intel Mac не выполнялись.
Отказ VPN в loopback-тесте моделируется отсутствующим интерфейсом;
аварии/отказы службы проверяются подменами зависимостей.

При DoH/ECH скрытое имя не всегда сопоставляется с доменным правилом:
тогда работают IP-правила, а без совпадения в режиме правил трафик идёт напрямую.
Это сохраняет предусмотренное поведение приложения.

Публикация релиза, изменение публичного канала и отправка в GitHub не выполнялись.

## Повтор проверки

```bash
bash scripts/test.sh
bash scripts/build.sh
AT_TEST_BUNDLE="$PWD/dist/AutoTurn.app" .build/core-tests
AT_TEST_ROUTING_CORE="$PWD/dist/AutoTurn.app/Contents/Resources/routing-core" .build/audit-tests
bash scripts/smoke.sh
python3 scripts/test-routing-runtime.py
/Applications/AutoTurn.app/Contents/MacOS/AutoTurn --routing-live-check-stored
```

Сборка требует подготовленного routing core через `scripts/prepare-routing-core.sh`.
Живой тест требует установленной совпадающей службы и исходного состояния
«дома», «выключено» либо «настройка» без блокировки. Перед ним нужно закрыть
обычный процесс AutoTurn, после него — запустить приложение снова.
Тест временно изменяет сеть и завершает работу в режиме Off;
он не записывает настройки в Keychain.

Логи в `.build`: `tests.log`, `bundle-tests.log`, `smoke.log`, `runtime.log`,
`feed.log`, `live-routing.log`, `install.log`.
