# AutoTurn — разработка и выпуск

> Актуальные команды и процесс выпуска находятся в разделе [«Выпуск 1.0 и новее»](#выпуск-10-и-новее). Описания 0.1.x ниже — история ранних проверок, а не текущие ограничения или расписание обновлений.

Нативный клиент AppKit для Intel и Apple Silicon. AmneziaWG 3.1, пульт и верхнее меню, подпись **powered by LENCHA_**.

На этом Intel Mac проверено реальное переключение «Вкл. → Авто дома → Вкл. → Выкл. → Авто дома» с пользовательским AmneziaWG-профилем и HTTPS через curl и системный URLSession на каждом шаге. Для «Авто дома» выдержана пауза 12 секунд. Пользователь также переключил Mac на другую Wi-Fi-сеть и обратно: зафиксированы автоматическое появление VPN-маршрутов/DNS и работа HTTPS вне дома, их удаление и прямой HTTPS дома. Нативный запуск приложения, движка, службы и IPC проверен на Apple Silicon/macOS 14 и 15 в GitHub Actions, включая опубликованный ZIP. Проверка конкретного VPN-сервера на Mac получателя и отказ реальных резервных серверов ещё нужны. Начиная с 1.0.4 мастер сам проверяет необходимые доступы и начинает установку/обновление службы при необходимости; системный запрос администратора подтверждает пользователь.

## Исправления 0.1.4

- Открытая шторка обновляет режим, статус, выбранный профиль и индикаторы при получении нового состояния. Повторное открытие не требуется; одинаковое состояние сохраняет существующие элементы.
- Опрос статуса раз в секунду при открытой шторке, раз в пять секунд в фоне. Сетевые события передаются сразу, контроль SSID — раз в три секунды; таймеры работают в common modes.
- Клик в другом окне приложения, в другом приложении или потеря активности закрывают шторку. Обработчики мыши существуют только пока она открыта; после закрытия удаляются. Клик внутри не закрывает её, повторный клик по значку переключает видимость.
- AppKit-проверка открывает настоящий NSPopover: проверяет обновление без закрытия, сохранение вида при одинаковом статусе, внутренний/внешний клик и освобождение наблюдателей. Профили/Keychain/сеть в этом тесте не меняются.
- Диагностический запуск `--observe-live-network` сообщает только состояния автоматики и признаки доступности сети/SSID/домашней сети, без ключей и адресов VPN-сервера.

## Исправления 0.1.3

- События изменения маршрутов/DNS самого VPN больше не сбрасывают известный домашний SSID. Наблюдение сети передаётся вместе с настройками и привязано к физическому интерфейсу и шлюзу; настоящая смена сети по-прежнему пересматривает решение.
- «Выключить» отправляет остановку сразу, до сохранения настроек в Keychain и проверки профилей. На домашней сети/при выключении сначала снимаются наши блокирующие правила, затем останавливается движок и убирается VPN DNS. Остановка движка ограничена по времени; ошибки очистки показываются.
- Сетевые обновления и таймеры продолжают работать при открытых меню/диалогах.
- Верхнее меню приведено к первому макету: ширина 292, AUTOTURN_ / HL100, индикатор состояния, три коротких режима, профили с отметкой/подписью/статусом, строки с иконками, разделители и powered by LENCHA_. Сохранены быстрый импорт и проверка обновлений. Верхняя иконка — щит.
- 71 проверка общей логики и 13 проверок переходов настоящего класса службы с подставными сетевыми зависимостями. Включены повторные события от VPN, свежая домашняя сеть, смена шлюза и ошибка снятия блокировки.

## Что реализовано

- Пульт закрывается без остановки приложения; верхнее меню остаётся доступным.
- Импорт `.conf`, включая S1–S4, диапазоны H1–H4, I1–I5, HeaderProtectionKey, ContentPaddingAddition, временные параметры AWG 3.1 и диапазон PersistentKeepalive. Неизвестные параметры и скрипты отклоняются, а не теряются молча.
- Несколько профилей, выбор и порядок резерва. В этой версии один Peer на профиль, весь трафик VPN; IPv6 вне туннеля блокируется.
- Авто / включён вручную / выключен вручную. Список домашних SSID, доступ через CoreWLAN с разрешением геолокации. SSID относится к физическому интерфейсу и имеет короткий срок актуальности.
- Keychain для профилей/настроек. Helper получает ключи только в памяти; после перезапуска ждёт приложение, сохраняя требование блокировки.
- Отдельная root-служба: запуск userspace AWG, utun, маршруты и отдельный DNS resolver. Управление через Unix socket с проверкой UID, PID, валидности подписи и установленного CDHash приложения.
- Изолированный PF-якорь `com.apple/autoturn`, отдельная ссылка включения PF. Нет перезаписи `/etc/pf.conf` или сброса корневого набора правил. При включении защиты сбрасываются существующие сетевые состояния, чтобы старые прямые соединения не обходили новые правила.
- Проверки HTTPS через конкретный utun; одного handshake недостаточно. Два адресата, успех одного достаточен. DNS участвует в этих запросах, отдельного индикатора диагностики DNS пока нет.
- Переход на следующий профиль после трёх неудачных проверок, ожидание при потере сети, повторные обходы с задержкой 30/60/120 секунд. На рабочем резерве остаёмся. При отказе всех профилей последний существующий туннель удерживается, прямой доступ автоматически не включается.
- Кнопка GitHub-обновлений: отдельные `macos-v…` релизы, подписанные Ed25519 сведения и архив, SHA-256, проверка версии/минимальной macOS, установка с повторной авторизацией службы. Релизы ещё не опубликованы.
- Запуск при входе, диагностика без ключей, подтверждение ручного отключения/завершения.

## Сборка

Нужны Command Line Tools / Xcode 16.4 либо совместимые более новые инструменты и Go. Установленный Go автоматически скачивает требуемый движком Go 1.25.0. Минимальная macOS приложения: **13.0**, совместимость с ней ещё нужно проверить на устройстве.

```sh
bash scripts/test.sh
bash scripts/build.sh
```

Результат: `dist/AutoTurn.app`, с нативными x86_64 и arm64 исполняемыми компонентами. `AT_ARCHS=x86_64` — только для локальных промежуточных сборок. Полноценный Xcode-проект не требуется: приложение собирается `swiftc`, исходники можно открывать и редактировать в Xcode.

Движок закреплён: [amneziawg-go v3.1.20260828](https://github.com/amnezia-vpn/amneziawg-go/tree/v3.1.20260828), коммит `b5928efb6ca19f0153958460c3d141f04abc5c2e`. Как в upstream Makefile, номер версии генерируется в `version.go`; UAPI-директория задаётся `/var/run/autoturn/uapi`. Это отделяет наш движок от других клиентов AmneziaWG. Лицензия движка включается в приложение.

Все компоненты имеют локальную ad hoc подпись. Developer ID/нотариализации нет. На другом Mac может понадобиться разрешение запуска конкретного приложения в настройках macOS; глобальное отключение защиты не требуется.

## Выпуск 1.0 и новее

Go 1.26.9; macOS 13+ deployment target. Routing core закреплён на sing-box 1.14.3, commit `7054cac5124465ffdb145870d7c01885566711b1`. `scripts/prepare-routing-core.sh` применяет отслеживаемые патчи, тестирует их и строит universal routing-core.

```sh
bash scripts/test.sh
bash scripts/prepare-routing-core.sh
bash scripts/build.sh
bash scripts/smoke.sh
bash scripts/package-candidate.sh
```

CI собирает кандидат и соответствующие исходники. Для подписи готового ZIP сначала извлеките его в `dist/AutoTurn.app`, затем:

```sh
python3 scripts/prepare-release.py --key /secure/location/autoturn-update.private --archive dist/candidate/AutoTurn-1.0.0-macOS.zip --notes releases/1.0.0/notes.md
```

Нужен Python с cryptography. Закрытый ключ не хранится в репозитории, CI или артефактах. Публичный ключ в Resources остаётся прежним: изменение сломает обновления старых клиентов. Не используйте `--init` для существующего канала обновлений.

Публикация запускается только при добавлении `releases/<version>/publish.json` и подписанных метаданных. Manifest фиксирует успешный CI run и точный SHA-256 архива. Pipeline проверяет подписи и соответствие версии, запускает именно этот ZIP нативно на Intel и Apple Silicon, затем публикует архив, метаданные, исходники и контрольные суммы. Тег указывает на исходный коммит кандидата.

Полные соответствующие исходники модифицированного routing-core и AWG входят в third-party-source архив. Архив содержит go.mod/go.sum, лицензии и скрипты сборки; версии и патчи также записаны в репозитории. Настоящие пользовательские `.conf` и ключ выпуска в архивы не включаются.

Приложение подписано ad hoc, без Developer ID/нотариализации. Проверка обновления использует Ed25519 архива и метаданных, SHA-256 и валидацию всех четырёх универсальных компонентов до остановки службы.

## Ключ обновлений 1.0.4

В 1.0.4 ключ Ed25519 сменён. Поэтому первый переход со старых релизов только ручной; прежний клиент не может проверить новую подпись. Приватный ключ хранится вне репозитория с доступом только владельцу. Не запускайте --init для следующих выпусков этого канала: используйте этот сохранённый ключ. CI-кандидат и обязательные проверки точного подписанного ZIP остаются прежними.
