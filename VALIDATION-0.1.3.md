# Проверка AutoTurn 0.1.3 — 11 октября 2026

Сборка установлена в `/Applications/AutoTurn.app`, служба обновлена и привязана к новой подписи. Все три исполняемых компонента содержат x86_64 и arm64; ad hoc подписи проверены. M1 физически не проверен.

## Автоматические проверки

71 проверка парсера AWG 3.1, общей политики, резервов и подписанных обновлений; 13 проверок переходов класса root-службы с подставными сетевыми зависимостями. Проверка AppKit: четыре вкладки, пустой/три профиля, ширины 700/760/1000, импорт и файловый pasteboard, геометрия меню 292 и профилей, диагностика, подпись LENCHA. Изображение меню получено рендером настоящих NSView, а не HTML-макетом.

## Реальная сеть на Intel Mac

Дважды пройден нормальный путь приложения/службы: Вкл. → Авто дома → Вкл. → Выкл. → Авто дома. Второй проход — окончательная сборка с новым меню. На каждом шаге HTTP 200 через curl и нативный URLSession; для каждого этапа Авто дома выдержана пауза 12 секунд. Подключение использовало предоставленный пользователем профиль в памяти; файл не включён в проект/архив. После прохода: наш PF-якорь пуст, журнал guard required=false, DNS роутера, нет split routes VPN, прямой HTTPS 200.

Пользователь затем реально переключил Wi-Fi на другую сеть и обратно при режиме Авто. Наблюдение: внешний шлюз 192.168.31.1, split routes 0/1 и 128.0/1 через utun4, VPN DNS 1.1.1.1 и HTTPS 200. После возврата: шлюз домашнего роутера 192.168.1.1, отсутствие split routes, DNS роутера и HTTPS 200. При обратном переходе около минуты отсутствовал физический default route; непрерывность во время переподключения Wi-Fi не заявляется.

Дополнительная попытка подключить Everest_new командой networksetup с сохранённым паролем вернула ошибку macOS -3924. Этот проход не считается подтверждённым тестом внешней сети. Скрипт вернул Keen_5G; после завершения нет VPN-маршрутов, DNS роутера и HTTPS 200. При временно неизвестном SSID автоматика может кратко включать защиту/VPN согласно согласованной политике.
